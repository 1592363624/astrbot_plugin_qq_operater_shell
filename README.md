## 功能说明

本插件仅支持QQ平台（aiocqhttp），提供QQ群管理操作功能。所有命令需要**管理员权限**。

### 命令列表

| 命令 | 说明 | 使用示例 |
|------|------|----------|
| `/获取群列表` | 获取机器人所在的所有QQ群列表 | `/获取群列表` |
| `/获取群成员信息` | 获取指定群中特定成员的详细信息 | `/获取群成员信息 722252868 1592363624` |
| `/模仿` | 让机器人模仿指定用户的头像和群名片 | `/模仿 @目标用户` 或 `/模仿 123456789` |
| `/停止模仿` | 停止当前模仿任务 | `/停止模仿` |
| `/更新头像` | 通过发送图片更新机器人头像 | `/更新头像`（然后发送图片） |
| `/更新头像URL` | 通过URL更新机器人头像 | `/更新头像URL http://example.com/avatar.jpg` |
| `/更新昵称` | 更改机器人的QQ昵称 | `/更新昵称 新昵称` |
| `/群发消息` | 群发消息到所有群或指定群 | `/群发消息 你好` 或 `/群发消息 你好 123456 789012` |
| `/潜水名单` | 查看按"最先进群且最久未发言"排序的潜水成员（只预览不踢人） | `/潜水名单`、`/潜水名单 20`、`/潜水名单 20 30 123456789` |
| `/清退潜水` | 批量踢出潜水成员（先展示名单，回复「确认」后才执行） | `/清退潜水 10`、`/清退潜水 10 30`、`/清退潜水 10 30 123456789` |
| `/踢出潜水` | 按天数批量踢出未发言成员（数量不指定则踢出全部符合条件的） | `/踢出潜水 30`、`/踢出潜水 30 10`、`/踢出潜水 30 10 123456789` |
| `加待办`（引用消息回复，无需前缀） | 将被引用的消息登记为反馈待办（自动容忍回复时自动携带的"@被引用人"前缀） | 引用某条消息回复：`加待办 这里有个bug` |
| `/待办列表` | 查看待办：无参数列出全部未完成；带编号查看该条详情（含聊天上下文、附图链接）；支持 `全部` / `已完成` 过滤 | `/待办列表`、`/待办列表 3`、`/待办列表 已完成` |
| `/完成待办` | 完成待办，并把处理结果引用回复给报告人 | `/完成待办 3 已修复并发布新版本` |
| `/删除待办` | 删除待办，支持批量 | `/删除待办 3`、`/删除待办 3 5 7`、`/删除待办 3-7`、`/删除待办 已完成`、`/删除待办 全部` |
| `/反馈` | **所有人可用**，返回免登录的网页反馈地址 | `/反馈` |
| `/反馈链接` | 查看或重置网页反馈地址（`重置` 会让旧链接失效） | `/反馈链接`、`/反馈链接 重置` |
| 插件页面「管理中心」 | 在 WebUI 中管理插件功能，当前含：反馈待办（编辑 AI 摘要、一键重新总结、完成并发送回复、批量删除）；后续新功能会以模块形式加入 | 插件详情页 → 管理中心 |

### 功能详情

#### 获取群列表
列出机器人所在的所有QQ群，显示群号和群名。

#### 获取群成员信息
查看指定群中特定成员的详细信息，包括：昵称、群名片、性别、年龄、地区、加入时间、最后发言时间、身份（群主/管理员/成员）、专属头衔。

#### 模仿功能
让机器人自动模仿指定用户的头像和群名片。支持：
- 通过@用户或QQ号指定模仿目标
- 定时检查目标用户信息变化并同步更新（默认每10分钟检查一次）
- 如果已有模仿目标，会询问是否替换
- 目标用户信息变化时自动更新机器人头像和群名片
- 使用MD5哈希检测头像变化，避免重复更新

#### 更新头像
通过发送图片或URL更新机器人头像。支持多种方式：
- 直接发送图片
- 通过URL更新
- 自动处理CQ码中的图片

#### 更新昵称
更改机器人的QQ昵称。

#### 群发消息
将消息发送到机器人所在的所有群或指定群：
- `/群发消息 消息内容` - 发送到所有群
- `/群发消息 消息内容 群号1 群号2 ...` - 发送到指定群

自动统计并返回成功/失败数量。

#### 潜水成员清退
按"最先进群且最久未发言"排序筛选群内潜水成员，支持预览与批量踢出：
- 排序规则：从未发言的成员排在最前（同为从未发言时，越早进群越靠前），其次按最后发言时间从早到晚
- 自动排除群主、管理员、机器人自身和指令发送者
- `/清退潜水`（数量优先）：`[数量] [静默天数] [群号]`，踢出排序前 N 名，静默天数可选过滤
- `/踢出潜水`（天数优先）：`[天数] [数量] [群号]`，踢出所有超过 N 天未发言（含从未发言）的成员；数量不指定时不设上限（指定时上限 50），群聊中群号缺省为当前群，私聊中最后一个数字视为群号
- 两个踢出指令执行前都会展示完整名单（超过 30 人时只列前 30 人并显示总数），管理员在 60 秒内回复「确认」才会执行，回复「取消」放弃
- `/潜水名单`（只预览）：`[数量] [静默天数] [群号]`，参数含义与 `/清退潜水` 相同
- 踢出逐个执行并按"消息发送间隔"配置设置间隔，避免操作过快触发风控；被踢成员不会被拒绝再次加群，误伤时可自行重新入群

#### 反馈待办
收集群友反馈的 Bug 和建议，形成带编号的待办清单，处理完成后自动引用回复报告人。支持两种收集方式：管理员在群里「引用消息 + 加待办」，或群友自己打开网页表单填写（见下方「网页反馈」）。

**前提配置**（插件配置页）：
- `todo_owner_qqs`：允许触发"加待办"的QQ号列表（WebUI 列表形式添加）。注意QQ需与机器人登录的QQ不同（机器人自己从手机发的消息不会进入消息事件）。
- `todo_context_size`：抓取被引用消息前后聊天记录的条数，默认前后各 10 条（依赖 NapCat/Lagrange 的 `get_group_msg_history` / `get_group_msgs_after_seq` 接口）。
- `todo_use_llm`：是否调用 AstrBot 当前聊天模型分析聊天记录、生成反馈摘要。
- `todo_reply_feedback`：添加/完成待办时是否回复确认消息（确认已登记、展示 AI 摘要让你检查效果；关闭后成功时静默处理、仅记录日志，出错仍会提示）。
- `todo_auto_delete_done`：待办完成并回复报告人后是否自动从列表删除（默认关闭保留已完成记录；开启后如需历史请用插件页面或别开）。

**WebUI 管理页面（管理中心）**：在 WebUI → 插件 → 本插件详情页打开「管理中心」页面（左侧导航按模块组织，新功能以后会以新模块加入）。当前包含「反馈待办」模块，可以：
- 按 未完成/已完成/全部 筛选查看所有待办（含聊天上下文与附图缩略图，点击缩略图可放大查看）；
- 直接编辑 AI 摘要与补充原因（机器人总结不准确时可手动修正）；
- 一键「重新总结」：基于已存储的上下文重新调用 LLM 并显示新结果；
- 「完成并发送回复」：填写处理结果后直接完成待办（同样会引用回复报告人）；
- 单条删除与勾选批量删除（删除时对应的本地附图文件一并清理）。

**使用流程**：
1. 群友在群里反馈问题后，用配置的QQ**引用（回复）那条消息**，发送 `加待办`（可带补充原因，如 `加待办 偶现，概率约10%`，无需指令前缀）。
2. 插件自动抓取该消息前后的聊天记录，调用 LLM 总结反馈内容，以自增编号存入待办列表，并记录来源群、报告人、被引用消息ID；随后机器人会把**登记确认和 AI 摘要回复出来**（可用 `todo_reply_feedback` 关闭），方便确认待办已添加、检查摘要效果。
3. 聊天记录中的**图片（如报错截图）会被提取并附送给 LLM 识别内容**（需多模态模型，最多附送8张且被引用消息的截图优先；模型不支持图片时自动降级为纯文本分析），同时转存到本地供插件页面长期查看（QQ 原始图片链接带时效签名会过期，本地副本在待办删除时自动清理）。
4. `/待办列表` 查看未完成待办，`/待办列表 <编号>` 查看某条待办的完整上下文。
5. 处理完成后执行 `/完成待办 <编号> <处理结果>`，机器人会**引用回复报告人最初的那条消息**并附上处理结果；若机器人已不在该群导致发送失败，待办保持未完成，可稍后重试。
6. 误登记的待办可用 `/删除待办 <编号>` 删除（编号不复用，新待办继续顺延）。

#### 网页反馈（群友自助提交）

除了管理员引用消息登记，群友也可以自己打开一个免登录的网页表单填写反馈，提交后**直接进入同一个待办列表**（编号、AI 摘要、附图、完成回复全部复用上面那套流程）。

**为什么用网页而不是 QQ 多轮问答**：表单能一次收齐「问题描述 + 复现步骤 + 发生时间 + 截图 + 联系方式」，还能在电脑上填；多轮对话里用户经常说一半就跑了，且图片容易被刷屏淹没。

**图文混排编辑器**：问题描述是一个富文本框，截图可以直接 `Ctrl+V` 粘贴进去、拖拽进去，或者点「添加图片」选文件，图片会插在光标所在位置，和文字混着写（像聊天窗口那样）。提交时按「文字 — 图片 — 文字」的原始顺序存下来，待办正文里用 `[图片1]`、`[图片2]` 标记图片位置，配合附图缩略图一眼就能对上。图片点一下可看大图，右上角 × 删除。

**群友怎么用**：
1. 在群里（或私聊机器人）发送 `/反馈`，机器人回复一条带令牌的链接；
2. 手机或电脑打开链接，选问题类型、在描述框里图文混着写（截图直接粘）、填发生时间和联系方式；
3. 点「提交反馈」，页面立刻返回反馈编号；
4. 处理完成后，若留了 QQ 号，机器人会私聊把处理结果发给他。

**管理员侧**：
- 收到反馈时默认私聊提醒（`web_notify_admins`），提醒里带编号，可直接 `/待办列表 <编号>` 看详情；
- `/反馈链接` 查看当前地址，`/反馈链接 重置` 立即作废旧链接；
- WebUI 管理中心的待办卡片会显示「网页反馈」来源、问题类型、复现步骤、联系方式，附图缩略图照常可看。

**部署说明（重要）**：
- 反馈页复用 AstrBot 面板（Dashboard）的 HTTP 端口，**不需要额外开放端口**。默认访问路径是 `http://<面板地址>/feedback`。
- 面板的鉴权中间件只拦截 `/api` 前缀，`/feedback` 属于公开路径，因此群友无需登录 AstrBot 账号即可访问。
- 如果你的面板端口不对外（只监听 127.0.0.1），需要通过 Nginx/Caddy 反代到公网，并在插件配置「反馈页对外地址」里填写反代后的前缀（如 `https://bot.example.com`）。
- 链接默认带访问令牌（`web_require_token`），避免地址被随意传播；令牌由插件自动生成并持久化。

**网页反馈相关配置**：

| 配置项 | 说明 |
|--------|------|
| `web_enabled` | 启用网页反馈，关闭后 `/feedback` 返回 404 |
| `web_base_url` | 群友能访问到的地址前缀，如 `https://bot.example.com:6185`（留空则按面板 host:port 推断，推断为 127.0.0.1 时群友访问不到） |
| `web_require_token` | 链接是否需要访问令牌（默认开启） |
| `web_max_images` | 单次最多上传图片数（默认 6） |
| `web_max_image_mb` | 单张图片体积上限（默认 5MB） |
| `web_notify_admins` | 收到反馈时私聊提醒管理员 |

**安全措施**：令牌常量时间比对、单 IP 滑动窗口限流（10 分钟 5 次）、图片按文件头识别真实类型（伪装成图片的文件直接丢弃）、文本长度与图片体积上限、页面带 `noindex` 与 `no-referrer` 头。
